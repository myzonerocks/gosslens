This is the complete guide for an Android app, in the order you will build in.

## Install

```kotlin
// build.gradle.kts
implementation("io.github.avosa:gosslens:0.14.0")
```

The AAR carries a `libgosslens.so` per ABI. The JNI layer is generated from the
C header and holds no logic of its own, which is why it has never disagreed
with the engine about a struct layout.

## Check the build before you trust it

```kotlin
import com.gosslens.*

check(Gosslens.abiCheck()) { "abi major mismatch" }
val version = Gosslens.abiVersion()
val caps = Gosslens.capabilities()
```

`capabilities()` returns the bitfield described in
[capabilities](/docs/concepts/capabilities). A stub build answers every call
and computes nothing.

## Engine and session

```kotlin
val engine = GossEngine.create(GossEngineConfig(texturePoolCapacity = 8u))
val session = GossSession.create(engine, GossSessionConfig(frameBudgetUs = 8_000u))
```

A null config means the core's own defaults, exactly as a null means in C.
`GossEngine.create` runs the ABI check itself, so a mismatch fails here rather
than somewhere unrelated later.

## Frames in

### The zero-copy path

CameraX frames reach the engine as `AHardwareBuffer` imports.

```kotlin
imageAnalysis.setAnalyzer(executor) { image ->
    val desc = GossFrameDesc(
        width = image.width.toUInt(),
        height = image.height.toUInt(),
        pixelFormat = GossPixelFormat.Nv12,
        rotationDegrees = image.imageInfo.rotationDegrees.toUInt(),
        mirrored = isFrontCamera,
        timestampUs = image.imageInfo.timestamp / 1000,
    )
    session.submitHardwareBuffer(desc, hardwareBufferOf(image))
    image.close()
}
```

Per-frame calls reuse direct byte buffers the session allocates once, rather
than allocating per frame. Keep your own descriptor object and mutate it.

### The copy paths

```kotlin
session.submitFrameCopy(y, yStride, uv, uvStride, width, height, rotation, mirrored, timestampUs)
session.submitFrameRgbaCopy(rgba, stride, width, height)
session.submitSourceFrameRgba(name, rgba, width, height)
```

Correct, and slower. Use them to bring a surface up, not to ship.

### Report the frame

```kotlin
val level = session.reportFrame(frameTimeUs, thermal)
val now = session.degradeLevel()
```

Map Android's own thermal reading onto `GossThermal` and pass it. Passing a
constant is how a phone ends up hot with the ladder still at full. See
[degradation](/docs/concepts/degradation).

### Events

```kotlin
val batch = session.pollEvents(capacity = 64)
// batch carries the events and the count dropped since the last drain
```

Events drain from the engine's ring with the count of anything missed since the
last drain, which a caller can wrap in a flow in one line. The SDK takes no
coroutines dependency of its own, so it does not decide your concurrency for
you.

Surface the dropped count. It is the only backpressure signal you get.

## Lenses

```kotlin

val value = session.parameterValue("spin_w")

```

`snapshotLensState` and `applyLensState` are what a configuration change needs:
an activity recreated on rotation can restore exactly what the lens was doing
rather than restarting it.

## AR

### ARCore in one object

```kotlin
val world = GossARCoreWorldSource(session)

// in your ARCore frame callback
world.onFrame(frame)
world.stop()
```

It submits the pose, the projection, the tracked planes, the anchors and the
light estimate from one ARCore `Frame`, into direct buffers it allocates once.

## Threads and lifetimes

An engine and its sessions belong to the thread that created them. On Android
the hazard is specific and common:

- **The garbage collector.** A finaliser runs on its own thread, and a destroy
  from there is a call from the wrong thread. Release explicitly when the
  feature ends.
- **CameraX executors.** Give the analyzer the same executor you create the
  engine on, or post to it.
- **Configuration changes.** An activity recreated on rotation must not create
  a second engine. Hold it where it survives, and restore the lens with
  `snapshotLensState` and `applyLensState`.

Destroy sessions before the engine. See [threads and
lifetimes](/docs/concepts/threading).
