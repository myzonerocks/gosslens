The web SDK is the same engine compiled to wasm. Nothing is uploaded and no
endpoint is called: a page that uses it works offline once loaded.

## Install

```bash
bun add @myzonerocks/gosslens
npm install @myzonerocks/gosslens
```

The package ships the wasm beside the wrapper. Serve the wasm from your own
origin and pass its URL when you load.

## Loading

```ts
import { Gosslens, GossSession } from '@myzonerocks/gosslens'

const goss = await Gosslens.load(canvas, wasmJsUrl)
const session = GossSession.create(goss.engine, { frameBudgetUs: 8_000 })
```

For a camera preview with the common wiring already done:

```ts
import { GossPreviewSession } from '@myzonerocks/gosslens'

const preview = await GossPreviewSession.create(canvas, wasmJsUrl, {
  onEvent: (event) => { /* ... */ },
})
```

Check the build before trusting it:

```ts
const version = goss.abiVersion()
const caps = goss.capabilities()
```

## Frames in

### From a texture

The fast path on the web hands the engine a texture you already have.

```ts
session.submitFrameTexture(texture, desc)
session.adoptTexture(texture)
session.releaseTexture(texture)
```

### From pixels

```ts
session.submitFrameRgbaCopy(pixels, canvas.width * 4, canvas.width, canvas.height)
session.submitFrameCopy(y, yStride, uv, uvStride, width, height, rotation, mirrored, timestampUs)
```

### A video element

```ts
import { GossVideoTexture } from '@myzonerocks/gosslens'

const video = new GossVideoTexture(session, 'clip', url)
await video.start()
video.pump()     // once per animation frame
video.stop()
```

### A shared screen

```ts
session.defineScreenShare(options)
session.openScreen(surfaceId, scale)
session.stepScreen(screen)
session.screenPoint(screen, x, y)
session.closeScreen(screen)
```

### Report the frame

```ts
const level = session.reportFrame(frameTimeUs, thermal)
session.reportInterruption(kind)
```

The browser gives you no thermal reading, so pass the nominal value and rely on
the measured frame time. The ladder still works; it just has one signal instead
of two.

### Trackers

Standalone trackers, when you want one without a full session:

```ts
import { GossFaceTracker, GossHandTracker, GossSegmenter } from '@myzonerocks/gosslens'

const tracker = new GossFaceTracker(/* ... */)
const result = tracker.process(rgba, width, height, timestampUs)

```

`GOSS_FACE_LANDMARK_COUNT` and `GOSS_FACE_BLENDSHAPE_COUNT` are exported, so a
caller sizes buffers from the SDK rather than from a number in a blog post.

## What the browser costs you

Two things differ from the native SDKs, and both are the platform rather than
the engine:

- **Threads depend on the page.** Worker threads need cross-origin isolation.
  Without `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy`, the
  engine runs single threaded and your budget has to reflect that.
- **Memory is the wasm heap.** Pool capacities that are comfortable on a phone
  can be expensive in a tab. Start at the defaults and read `engineReport` for
  the pools' live and peak counts.

## Keeping the main thread free

The main thread is also the one painting. Submit, render and read on the same
animation frame, and never await a network request between submitting a frame
and reading its record.

```ts
function frame(now: number) {
  session.submitFrameTexture(texture, desc)
  session.tickLens(dtUs, signals)
  session.renderFrame()
  const json = session.perceptionJson()
  session.pollEvents()
  session.reportFrame(frameTimeUs, thermal)
  requestAnimationFrame(frame)
}
```

## Lifetimes

```ts
session.destroy()
session.release()
```

Destroy the session before the engine, and do not let a framework's cleanup run
it twice from different places. See [threads and
lifetimes](/docs/concepts/threading).
