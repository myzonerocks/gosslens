# Roadmap

Gosslens is a camera and AR engine. New capabilities are built on the
pieces that already exist: the tracking module's model path, the lens
format's node and trigger system, and the bgfx render graph, rather than
as separate machinery.

Work is ordered by dependency, so a stage builds on a tracker, material
system, or runtime an earlier stage added. Each stage merges as one squash
PR with a conformance proof for what it adds. The sections below group each
area's built work with what is still planned, so everything about one area
is in one place.

## Foundations

- [x] Repo scaffold: pinned toolchain, source gate, hooks, CI
- [x] Math: SIMD vectors, matrices, quaternions, poses, color conversion
- [x] Frame graph: nodes, typed edges, cached schedule, pooled textures and buffers, the degradation ladder
- [x] C ABI: gosslens.h, the goss_ exports, the ABI diff gate
- [x] Render and assets: bgfx backend node, glTF loading, capture ingress on the client SDKs
- [x] Conformance: the headless harness and corpora exist and gate CI; a session-lifecycle leak gate runs many activate/tick/destroy cycles of the adapter-heavy lenses under a leak-checking allocator and fails on any memory still held at teardown; and a per-frame budget gate renders the heaviest reference stack (blur, grade, bloom and particles at once) for many frames under a counting allocator and fails on any steady-state heap growth - a deterministic, machine-independent guard on the quadratic-work and slow-leak class that overheats a phone. Device leak gates on real hardware are the remaining follow-up
- [x] SDKs: five packages ship - the Swift, Kotlin and web wrappers, the C SDK, and the Android JNI binding - each with a demo app and wrapper conformance to the API contract holding as of the sdk-conformance pass. The three client wrappers are publishable at a shared 0.1.0: the Swift package installs over a git URL with its C module, the Kotlin library publishes to a Maven coordinate (and resolves over JitPack) packaging the zig-built .so, and the web SDK builds to dist with types and an npm publish config over the wasm core the caller supplies. The C SDK (sdk/c) is a full-parity package reaching every one of the 113 ABI ops straight through the canonical header, with a static and shared library built by `zig build c`, a README, a demo, and a CMake build, so any host with a C FFI links the engine without a hand-written wrapper; the Android JNI binding (adapters/android/jni.zig) is landed alongside it
- [ ] A cross-cutting SDK sweep so every ABI op has a typed, documented wrapper on the Swift, Kotlin and web platforms, with ergonomic client facades and demo coverage of every op. The C SDK already reaches every op through the header and the JNI binding is landed, so what remains is the typed-wrapper and per-op demo work on the three client SDKs

## Lens format and scripting

- [x] Lens format: spec, manifest/trigger/animation runtime, graph splice/unsplice, validator, fuzzers; shader pass, LUT, blend, and glTF draw node types; four reference lenses shipped (shader-tint, beauty-baseline, background-swap, trigger-anim)
- [x] Scripting: a sandboxed per-lens script node backed by QuickJS-ng, with the signal and parameter surface as its API - a global update(lens) reads the current signals (the six live signals plus every ARKit blendshape by name, so a script reacts to an expression the way a trigger reads jawOpen.blendshape, proven by the script-expression reference lens) and writes the lens parameters each tick, with no filesystem, network, wall clock, or randomness in scope and a fuel bound so it can never hang; proven bit-stable in conformance (a script drives a parameter from a signal, read back through goss_session_parameter_value) and by module tests (deterministic tick, a runaway stopped by fuel); the QJS backend is now compiled real on host, android, ios, and web (wasm32-emscripten), so a scripted lens runs on device and in the browser, not just the harness; only wasm32-freestanding keeps the stub, since it has no libc to link the C against
- [ ] An expanded script event model (init, tap, swipe, pinch, rotate and custom events), touch and gesture interaction components, a screen-transform UI system, and a node-graph visual scripting surface over the same runtime
- [ ] A bring-your-own-model slot for ONNX and TFLite nets with input/output texture and tensor binding, in a signed, fuel-bounded, deterministic sandbox under the same license and digest gates as vendored models

## Tracking and scene understanding

- [x] Tracking: MediaPipe-class face pipeline behind a C shim, model fetching against a tracked lock
- [x] Hands: palm detection and hand landmarks on the existing tracking rail, up to two hands with handedness and canned gestures, goss_hand_* mirroring the face surface, Swift/Kotlin wrappers and demo overlays, proven on the pinned corpus through the public surface; the hands-present signal feeds lens triggers; the web hand pipeline is built (GossHandTracker over the wasm tracking module), with per-gesture trigger signals still open
- [x] Segmentation: the multiclass model on the segmentation worker with per-class masks, named mask channels for shader passes, and the hair-recolor reference lens, proven on the corpus and bit-stable in conformance; on-device visual passes not yet run on hardware
- [x] Pose: the 33-point body landmark pipeline on the tracking rail with per-point visibility and presence, goss_pose_* mirroring the face surface, Swift/Kotlin wrappers and demo overlays, proven on a pinned standing-figure corpus frame through the public surface; skeleton attachment points ride the anchor-node family alongside head pose, now landed
- [x] Head pose: weighted similarity fit of the canonical face's metric geometry to the live landmarks (deterministic, allocation-free), goss_session_face_pose with Swift/Kotlin wrappers, the model.gltf face-anchor node posing glTF content in canonical centimeter space, and the face-mask reference lens proven bit-stable on the pinned portrait corpus; skeleton anchors ride the same anchor field, now landed
- [x] Face-mesh effects: the canonical 468-point topology over the tracked landmarks as the mesh.face lens node, with the face-paint reference lens proven bit-stable in conformance with real tracking; makeup and mask variants ride the same node with their own textures
- [x] World tracking: goss_session_submit_world (pose, projection, planes, anchors, light) driving the world.tracking_state trigger and world-anchored glTF content drawn from the platform camera, proven bit-stable on a deterministic replay orbit with the world-anchor reference lens; all three backends written - ARKit WorldSource (compile-proven, device run pending hardware), the ARCore demo feeder, and the WebXR source with typed submitWorld on the web SDK (device and browser runs pending hardware); depth/occlusion into the mask rail is the named follow-up
- [x] Multi-face and body rig: the multi-face path carries up to four tracked faces (goss_session_face_count and goss_session_face_result_at) with the render fanning out per face, and a humanoid body rig exposes the pose as named joints - goss_session_body_joint over head, shoulders, elbows, wrists, hips, knees and ankles, plus analytic two-bone IK (goss_solve_two_bone_ik) and a skeleton anchor that poses glTF content off the joints, proven by the skeleton-rig reference lens
- [ ] Tracking depth: eye and gaze tracking with iris landmarks, a hand-gesture grammar as trigger signals, and new trackers for pet faces and feet
- [ ] Scene depth: a depth texture and monocular depth estimation feeding occlusion, a reconstructed world mesh, and sky, ground, building and per-region segmentation with a refined portrait matte

## Rendering, materials, and effects

- [x] Material graphs, animation, and 2D objects: a shader.pass node can author its fragment shader as a node graph (uv, sample, arithmetic, mix, step and the rest) lowered to GLSL and compiled at package time, proven end to end (material-tint renders real content, with vignette, posterize, pixelate, edge and a region-clip all authored purely as graphs). The glTF animation mixer decodes every clip and blends their sampled poses by weight, a lens binding each clip's weight to a live parameter (clip_weights) so a param_ramp with easing crossfades between animations; morph targets (blendshapes) deform the mesh by per-target weights bound the same way (morph_weights) - both conformance-proven (anim-mixer, morph-blend). And 2D content draws over the frame as its own node types: a sprite.2d image at a normalized rect and a text.2d string rasterized from a built-in bitmap font, each with a reference lens and a proof (sprite-overlay, text-overlay)
- [x] Post-effect passes: the primitives stand on their own as lens node types, each with a reference lens and a conformance proof - a separable blur (blur.pass), a parametric color grade of exposure/contrast/saturation/temperature (grade.pass), and a highlight bloom (bloom.pass); over the host's submitted depth a depth-of-field (dof.pass), a depth fog (fog.pass) and a depth-edge outline (outline.pass) all ship proven; a motion trail echoes the previous frame (trail.pass) and a screen-space reflection wets a floor by depth (ssr.pass); and halftone and a tilt-shift focus author as material graphs
- [x] Appearance and matte passes stand as their own lens node types too, each with a reference lens and a conformance proof: a masked colour tint (tint.pass) folding its colour into a named mask channel by a normal, multiply or screen blend, an edge-aware skin smooth (smooth.pass), a guided matte refinement over a segmentation channel (matte.refine), an artistic stylize (stylize.pass, the toon, sketch, emboss and crosshatch modes), an edge detector (edge.pass, Sobel and Canny), and a screen-space warp (warp.pass, bulge, pinch and swirl)
- [x] Sky and 2D textures: a procedural sky dome behind the segmented foreground pans with the camera pose, and an image-based equirect environment map samples a shipped panorama by that pose (env.pass, both proven); animated GIF clips play as sprite video textures (proven)
- [x] A separable two-axis DoF blur with a bokeh disc kernel over the depth (dof.pass), MP4 video textures decoded off the platform's hardware decoder and streamed frame by frame onto a sprite over the GossMedia rail (video.texture - a real recorded clip is proven decoding, advancing off the frame clock, looping, and holding when paused), and gradient, shadow, stroke and extruded 3D block-mesh styling over the sprite and text nodes - each primitive with a reference lens and a conformance proof

## Simulation: physics and particles

- [x] Physics: rigid bodies drive lens content - the physics field on model.gltf nodes (box/sphere, static/dynamic), per-lens worlds stepped from frame timestamps, proven deterministic by the physics-drop reference lens; constraint chains on kinematic anchors and distance constraints, proven by the earring reference lens; cloth sheets, a cloth field on model.gltf nodes with Jolt soft bodies driving a dynamic mesh, proven to drape by the flag reference lens; and Jolt 5.6 strand hair, a hair field on model.gltf with compute-backed soft strands driven by the head pose and drawn as lines, proven to settle by the hair reference lens; all four bit-stable through the public surface, with device targets and the on-device head-driven hair swing the named follow-up
- [x] Particles: a particles field on a model.gltf node runs a deterministic CPU fountain (emit, integrate under gravity, respawn) whose positions stream to a bgfx mesh each frame, drawn over the camera; the system is fully fledged - ten emission shapes (fountain, rain, burst, ring, cone, sphere, box, disc, hemisphere, and face - the AR spawn straight off the tracked landmarks), a full force set (drag, wind, turbulence, a gravity-well attractor, an orbital vortex, floor bounce), per-particle speed/lifetime spread and one-shot bursts, and camera-facing sprites carrying size-over-life, colour-over-life, spin, velocity stretch for streaks, additive glow, a textured sprite, and sprite-sheet flip-book animation - each conformance-proven (ember/snow/confetti/star/face-sparkle reference lenses) and bit-stable, with module tests over every pattern and force
- [x] Simulation depth deepens both halves. The particle side is complete: curl-noise turbulence, a named VFX preset library (fire/smoke/magic/sparks) that expands to the curated configs, particle trails and solid ribbons, sphere/box/plane colliders with configurable bounce, 3D-mesh particles (octahedron/cube/tetra), sub-emitters that burst a shell of children on death (the spawn-into-spawn a VFX graph composes), and a GPU-compute path that runs the fountain in a compute shader kept in sync with the CPU baseline (pixel-identical, the engine's first bgfx compute use, CPU fallback where the backend lacks compute) now carrying the full force set beyond gravity on that compute path (drag, wind, turbulence, curl noise, a gravity-well attractor and an orbital vortex; the exact-op forces keep the GPU pixel-identical to the CPU, and a one-frame emit offset between the two was fixed so they stay in lockstep). On the physics side: box/sphere/cylinder/capsule collider shapes plus convex-hull and concave triangle-mesh colliders, per-body orientation and a friction/restitution surface material, the full joint family (distance/point/fixed/hinge/spring), declarative jiggle and dynamic chains, a pressurised soft-body balloon and free soft bodies that collide with rigid geometry, planar bodies that compose a 2D collider world (a planar sphere a circle collider, a planar hull a polygon collider, a spring between planar bodies a 2D spring), trigger volumes, kinematic-anchor drive, and a nav mesh with A* pathfinding; and, newly, physics against a world-anchored mesh, a mesh collider built from a node's own glb, grab-and-throw of a dynamic body by a pointer, a 2D SPH fluid that pools under gravity, a head collider driven off the tracked head pose that lens content collides with, and erasable live colliders a pointer draws in and rubs out (content lands on them at once, and rests bodies fall when the collider under them is erased) - each with a reference lens and a conformance proof (or module tests for the pure algorithms), all bit-stable
- [x] The final simulation reach: GPU mesh instancing - a 3D-mesh particle cloud draws in one instanced call (each particle's model matrix on an instance buffer, the instanced twin of the lens vertex stage) instead of one draw per particle, proven to render the same image as the per-draw cloud (`proveMeshInstancing`, `lenses/reference/mesh-instanced` vs `mesh-plain`). The simulation-depth wave is complete.

## Media, audio, and capture

- [x] Media: deterministic PNG photo capture, platform photo formats with EXIF intact (JPEG/HEIC, decode-back proved), zero-copy video recording with an aligned audio track (goss_session_submit_audio feeding level and beat triggers plus the muxed track, zero end drift proved), libyuv behind adapters/image as the one CPU conversion authority; the MediaCodec backend is built on the encoder input surface (device proof pending hardware, video-only until its audio encoder lands)
- [x] High-resolution capture: full-resolution stills decoupled from the preview, supersampled (rendered larger, box-downsampled) for photo-grade anti-aliased edges, and tiled composition that breaks the texture-size ceiling on very large captures by compositing the output in tiles and stitching them on the CPU, all proven through the public ABI (full-sensor size recovered, supersampling deterministic and pixel-different from 1x, tiling byte-identical to a single-target render on 2x2 and 3x2 grids). Tiling covers 3D content too: each tile draws the model, cloth, hair and particle nodes through its own off-center sub-frustum, built from the whole frame's aspect so the scene keeps its shape and cropped in clip space to the tile, so the full AR scene composites past the per-platform texture ceiling, and an 8192-capped mobile GPU still produces a stitched capture well beyond 8K. Photo encoding is the engine's own: a built-in baseline JPEG encoder with standard tables and fixed rounding produces lossy stills on every target, deterministic and never gated on a platform encoder (HEIC keeps the platform path). Color management ships too: captures tag their gamut, PNG through cHRM/gAMA and JPEG through a matrix-shaper ICC built from the primaries (Bradford-adapted to the D50 profile connection space), for sRGB, Display-P3 and Rec2020; a 16-bit PNG output path carries a real high-bit-depth container. Proven through the public ABI and by module tests over the encoder, the ICC assembly and the color chunks; a fully 16-bit-float compositing chain for genuine HDR is the named follow-up
- [x] Audio: lens audio playback on miniaudio behind an engine boundary - a play_sound trigger action starts a voice on a deterministic mixer that decodes each sound once (no device, no clock) and sums active voices, pulled out as PCM through goss_session_pull_audio for the SDK to route to the platform; the level and beat signals already feed the trigger system from the media rail; proven bit-stable in conformance with the sound-beat reference lens and by a module test on the mixer; the miniaudio backend is compiled real on host, android, ios, and web (wasm32-emscripten) now; on-device output routing rides the SDK's platform audio, the named follow-up
- [ ] An audio suite: voice and speech recognition and a voice UI, text-to-speech, voice effects (pitch/formant/conversion), audio-driven lip-sync, spatial audio, beat-marker timelines, noise suppression, voiceover recording, music identification, and the real web audio mixer
- [ ] A capture and editing suite: dual-camera layouts, segmented multi-clip recording, a multi-track timeline, speed ramps and slow-mo/reverse/boomerang, a transitions library, beat-synced templates, green-screen editing, camera-roll import as a first-class source, drafts and a cover-frame picker, photo and text-post modes, and per-clip color adjustments
