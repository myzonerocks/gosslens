# Roadmap

Gosslens is a camera and AR engine. New capabilities are built on the
pieces that already exist: the tracking module's model path, the lens
format's node and trigger system, and the bgfx render graph, rather than
as separate machinery.

Work is ordered by dependency, so a stage builds on a tracker, material
system, or runtime an earlier stage added. Each stage merges as one squash
PR with a conformance proof for what it adds. The sections below group each
area's built work with what is still planned, so everything about one area
is in one place.

## Foundations

- [x] Repo scaffold: pinned toolchain, source gate, hooks, CI
- [x] Math: SIMD vectors, matrices, quaternions, poses, color conversion
- [x] Frame graph: nodes, typed edges, cached schedule, pooled textures and buffers, the degradation ladder
- [x] C ABI: gosslens.h, the goss_ exports, the ABI diff gate
- [x] Render and assets: bgfx backend node, glTF loading, capture ingress on the client SDKs
- [x] Conformance: the headless harness and corpora exist and gate CI; a session-lifecycle leak gate runs many activate/tick/destroy cycles of the adapter-heavy lenses under a leak-checking allocator and fails on any memory still held at teardown; and a per-frame budget gate renders the heaviest reference stack (blur, grade, bloom and particles at once) for many frames under a counting allocator and fails on any steady-state heap growth - a deterministic, machine-independent guard on the quadratic-work and slow-leak class that overheats a phone. Device leak gates on real hardware are the remaining follow-up
- [x] SDKs: the Swift, Kotlin and web wrappers, the C SDK, and the Android JNI binding all ship - each with a demo app and wrapper conformance to the API contract holding as of the sdk-conformance pass. The three client wrappers are published at a shared version: the Swift package installs over a git URL with its C module, the Kotlin library publishes to a Maven coordinate (and resolves over JitPack) packaging the zig-built .so, and the web SDK builds to dist with types and an npm publish config over the wasm core the caller supplies. The C SDK (sdk/c) is a full-parity package reaching every ABI op straight through the canonical header, with a static and shared library built by `zig build c`, a README, a demo, and a CMake build, so any host with a C FFI links the engine without a hand-written wrapper; the Android JNI binding (adapters/android/jni.zig) is landed alongside it
- [x] A cross-cutting SDK sweep brought the Swift, Kotlin and web wrappers to 1:1 feature parity: an ABI cross-check surfaced the remaining wrapper gaps and closed them (Swift gained the named geofences, Kotlin the producer-path segmentation, TS the in-engine tracking, beauty, result-readback and NV12 ops), so every goss_ operation is reachable through a typed wrapper on all three platforms, with the surface tabled op by op in API.md - where a native-only symbol (recording to a path, a hardware buffer, a filesystem lens bundle) maps to the web-native method that serves it, so the parity is explicit rather than a gap. The two native SDKs carry the house format configs the other packages use (SwiftFormat and SwiftLint, an editorconfig and ktlint). Each SDK ships one feature-rich demo - the Swift, Kotlin, web and C consumers all show a live mirrored preview, a beauty panel, face, hand and pose overlays, a lens picker, a virtual-background toggle over the source segmenter, and photo capture - consuming the SDK from its local path with its conformance and prover hooks intact. The C SDK reaches every op through the header and the JNI binding is landed

## Lens format and scripting

- [x] Lens format: spec, manifest/trigger/animation runtime, graph splice/unsplice, validator, fuzzers; shader pass, LUT, blend, and glTF draw node types; reference lenses shipped (shader-tint, beauty-baseline, background-swap, trigger-anim)
- [x] Scripting: a sandboxed per-lens script node backed by QuickJS-ng, with the signal and parameter surface as its API - a global update(lens) reads the current signals (the live signals plus every ARKit blendshape by name, so a script reacts to an expression the way a trigger reads jawOpen.blendshape, proven by the script-expression reference lens) and writes the lens parameters each tick, with no filesystem, network, wall clock, or randomness in scope and a fuel bound so it can never hang; proven bit-stable in conformance (a script drives a parameter from a signal, read back through goss_session_parameter_value) and by module tests (deterministic tick, a runaway stopped by fuel); the QJS backend is now compiled real on host, android, ios, and web (wasm32-emscripten), so a scripted lens runs on device and in the browser, not just the harness; only wasm32-freestanding keeps the stub, since it has no libc to link the C against
- [x] An expanded script event model: host-fired events (goss_session_fire_event) fire lens triggers, tap/double-tap/long-press/swipe/pinch/rotate/drag touch signals and gesture interaction ride the trigger and script runtime, and a node-graph logic surface (logic.graph) wires signals to actions without a script
- [x] Interactive on-screen elements: a sprite.2d node anchored at a screen-space rect carries an interaction block (drag, pinch, rotate, and a tap_event that fires a named lens event on a hit), so a lens lays out buttons and panels the user drives, proven by the interactive-sprite reference lenses and the sprite-interaction module test
- [x] A bring-your-own-model slot: an ml.infer node runs a lens-supplied ONNX or TFLite net (model.tflite and cls/seg/style/unet.onnx bundle nodes) and binds its outputs to lens parameters (a scalar element or an argmax class), a whole tensor as a segmentation mask, or a stylized RGB image drawn over the frame, under the model digest and license gates in the deterministic, fuel-bounded inference sandbox, proven in the host harness

## Rendering, materials, and effects

- [x] Material graphs, animation, and 2D objects: a shader.pass node can author its fragment shader as a node graph (uv, sample, arithmetic, mix, step and the rest) lowered to GLSL and compiled at package time, proven end to end (material-tint renders real content, with vignette, posterize, pixelate, edge and a region-clip all authored purely as graphs). The glTF animation mixer decodes every clip and blends their sampled poses by weight, a lens binding each clip's weight to a live parameter (clip_weights) so a param_ramp with easing crossfades between animations; morph targets (blendshapes) deform the mesh by per-target weights bound the same way (morph_weights) - both conformance-proven (anim-mixer, morph-blend). And 2D content draws over the frame as its own node types: a sprite.2d image at a normalized rect and a text.2d string rasterized from a built-in bitmap font, each with a reference lens and a proof (sprite-overlay, text-overlay)
- [x] Post-effect passes: the primitives stand on their own as lens node types, each with a reference lens and a conformance proof - a separable blur (blur.pass), a parametric color grade of exposure/contrast/saturation/temperature (grade.pass), and a highlight bloom (bloom.pass); over the host's submitted depth a depth-of-field (dof.pass), a depth fog (fog.pass) and a depth-edge outline (outline.pass) all ship proven; a motion trail echoes the previous frame (trail.pass) and a screen-space reflection wets a floor by depth (ssr.pass); and halftone and a tilt-shift focus author as material graphs
- [x] Appearance and matte passes stand as their own lens node types too, each with a reference lens and a conformance proof: a masked colour tint (tint.pass) folding its colour into a named mask channel by a normal, multiply or screen blend, an edge-aware skin smooth (smooth.pass), a guided matte refinement over a segmentation channel (matte.refine), an artistic stylize (stylize.pass, the toon, sketch, emboss and crosshatch modes), an edge detector (edge.pass, Sobel and Canny), and a screen-space warp (warp.pass, bulge, pinch and swirl)
- [x] Sky and 2D textures: a procedural sky dome behind the segmented foreground pans with the camera pose, and an image-based equirect environment map samples a shipped panorama by that pose (env.pass, both proven); animated GIF clips play as sprite video textures (proven)
- [x] Model lighting: a model.gltf node opts into real shading instead of a flat draw. An opt-in directional light shades the mesh by its surface normal so the light's direction genuinely drives the result (proven a front-lit sphere diverges from a back-lit one over most covered pixels, and both from the unlit sphere); a sky-white ground-black hemisphere ambient grades a model along its normal's up-component (proven the two halves read apart where a uniform ambient reads even); and the glTF PBR material factors fold into the lit fragment shader (fs_model_lit), the base color tinting and the emissive channel lifting the surface (proven an emissive triangle averages brighter than the same triangle with none). The lighting reaches deforming meshes, not only static ones: a morph-target mesh shades through the lit dynamic path with its normals recomputed each frame (proven the lit morph mesh diverges from the unlit one), and the skinned path lights through that same per-frame recompute. Each proof deterministic across runs
- [x] A separable two-axis DoF blur with a bokeh disc kernel over the depth (dof.pass), MP4 video textures decoded off the platform's hardware decoder and streamed frame by frame onto a sprite over the GossMedia rail (video.texture - a real recorded clip is proven decoding, advancing off the frame clock, looping, and holding when paused), and gradient, shadow, stroke and extruded 3D block-mesh styling over the sprite and text nodes - each primitive with a reference lens and a conformance proof

## Simulation: physics and particles

- [x] Physics: rigid bodies drive lens content - the physics field on model.gltf nodes (box/sphere, static/dynamic), per-lens worlds stepped from frame timestamps, proven deterministic by the physics-drop reference lens; constraint chains on kinematic anchors and distance constraints, proven by the earring reference lens; cloth sheets, a cloth field on model.gltf nodes with Jolt soft bodies driving a dynamic mesh, proven to drape by the flag reference lens; and Jolt 5.6 strand hair, a hair field on model.gltf with compute-backed soft strands driven by the head pose and drawn as lines, proven to settle by the hair reference lens; all bit-stable through the public surface, with device targets and the on-device head-driven hair swing the named follow-up
- [x] Particles: a particles field on a model.gltf node runs a deterministic CPU fountain (emit, integrate under gravity, respawn) whose positions stream to a bgfx mesh each frame, drawn over the camera; the system is fully fledged - emission shapes (fountain, rain, burst, ring, cone, sphere, box, disc, hemisphere, and face - the AR spawn straight off the tracked landmarks), a full force set (drag, wind, turbulence, a gravity-well attractor, an orbital vortex, floor bounce), per-particle speed/lifetime spread and one-shot bursts, and camera-facing sprites carrying size-over-life, colour-over-life, spin, velocity stretch for streaks, additive glow, a textured sprite, and sprite-sheet flip-book animation - each conformance-proven (ember/snow/confetti/star/face-sparkle reference lenses) and bit-stable, with module tests over every pattern and force
- [x] Simulation depth deepens both halves. The particle side is complete: curl-noise turbulence, a named VFX preset library (fire/smoke/magic/sparks) that expands to the curated configs, particle trails and solid ribbons, sphere/box/plane colliders with configurable bounce, 3D-mesh particles (octahedron/cube/tetra), sub-emitters that burst a shell of children on death (the spawn-into-spawn a VFX graph composes), and a GPU-compute path that runs the fountain in a compute shader kept in sync with the CPU baseline (pixel-identical, the engine's first bgfx compute use, CPU fallback where the backend lacks compute) now carrying the full force set beyond gravity on that compute path (drag, wind, turbulence, curl noise, a gravity-well attractor and an orbital vortex; the exact-op forces keep the GPU pixel-identical to the CPU, and a one-frame emit offset between the two was fixed so they stay in lockstep). On the physics side: box/sphere/cylinder/capsule collider shapes plus convex-hull and concave triangle-mesh colliders, per-body orientation and a friction/restitution surface material, the full joint family (distance/point/fixed/hinge/spring), declarative jiggle and dynamic chains, a pressurised soft-body balloon and free soft bodies that collide with rigid geometry, planar bodies that compose a 2D collider world (a planar sphere a circle collider, a planar hull a polygon collider, a spring between planar bodies a 2D spring), trigger volumes, kinematic-anchor drive, and a nav mesh with A* pathfinding; and, newly, physics against a world-anchored mesh, a mesh collider built from a node's own glb, grab-and-throw of a dynamic body by a pointer, a 2D SPH fluid that pools under gravity, a head collider driven off the tracked head pose that lens content collides with, and erasable live colliders a pointer draws in and rubs out (content lands on them at once, and rests bodies fall when the collider under them is erased) - each with a reference lens and a conformance proof (or module tests for the pure algorithms), all bit-stable
- [x] The final simulation reach: GPU mesh instancing - a 3D-mesh particle cloud draws in one instanced call (each particle's model matrix on an instance buffer, the instanced twin of the lens vertex stage) instead of one draw per particle, proven to render the same image as the per-draw cloud (`proveMeshInstancing`, `lenses/reference/mesh-instanced` vs `mesh-plain`). The simulation-depth wave is complete.

## Media, audio, and capture

- [x] Media: deterministic PNG photo capture, platform photo formats with EXIF intact (JPEG/HEIC, decode-back proved), zero-copy video recording with an aligned audio track (goss_session_submit_audio feeding level and beat triggers plus the muxed track, zero end drift proved), libyuv behind adapters/image as the one CPU conversion authority; the MediaCodec backend is built on the encoder input surface, muxing an AAC audio track alongside the video through a second encoder (device proof pending hardware)
- [x] High-resolution capture: full-resolution stills decoupled from the preview, supersampled (rendered larger, box-downsampled) for photo-grade anti-aliased edges, and tiled composition that breaks the texture-size ceiling on very large captures by compositing the output in tiles and stitching them on the CPU, all proven through the public ABI (full-sensor size recovered, supersampling deterministic and pixel-different from 1x, tiling byte-identical to a single-target render on 2x2 and 3x2 grids). Tiling covers 3D content too: each tile draws the model, cloth, hair and particle nodes through its own off-center sub-frustum, built from the whole frame's aspect so the scene keeps its shape and cropped in clip space to the tile, so the full AR scene composites past the per-platform texture ceiling, and an 8192-capped mobile GPU still produces a stitched capture well beyond 8K. Photo encoding is the engine's own: a built-in baseline JPEG encoder with standard tables and fixed rounding produces lossy stills on every target, deterministic and never gated on a platform encoder (HEIC keeps the platform path). Color management ships too: captures tag their gamut, PNG through cHRM/gAMA and JPEG through a matrix-shaper ICC built from the primaries (Bradford-adapted to the D50 profile connection space), for sRGB, Display-P3 and Rec2020; a 16-bit PNG output path carries a real high-bit-depth container. Proven through the public ABI and by module tests over the encoder, the ICC assembly and the color chunks. And the fully 16-bit-float compositing chain for genuine HDR now ships: an hdr lens allocates half-float composite targets so a pass grading a highlight past 1.0 and back recovers it through the half-float intermediate where the 8-bit chain clips it, proven deterministic in conformance
- [x] Audio: lens audio playback on miniaudio behind an engine boundary - a play_sound trigger action starts a voice on a deterministic mixer that decodes each sound once (no device, no clock) and sums active voices, pulled out as PCM through goss_session_pull_audio for the SDK to route to the platform; the level and beat signals already feed the trigger system from the media rail; proven bit-stable in conformance with the sound-beat reference lens and by a module test on the mixer; the miniaudio backend is compiled real on host, android, ios, and web (wasm32-emscripten) now; the mixed PCM routes to the platform speaker through a per-SDK output sink - AVAudioEngine on iOS, AudioTrack on Android, an AudioWorklet on web - that the frame loop pumps over a ring, device playback pending hardware
- [x] Multi-source compositing: a session defines named sources beyond the camera, each submitting its own frames and placed by a layout, with per-source opacity and keying - a supplied per-source mask (key mode 3) cuts a source to its subject, and a chroma key against a screen colour both keys the source and suppresses the green spill left on the kept subject, each proven through the public ABI. And the engine computes the matte itself: a per-source virtual-background segmenter runs the selfie model on a source's own frames on-device, filling that source's key-mode-3 matte with no host-supplied mask (proven the engine-computed matte reaches the source composite, keyed on device). The web SDK exposes the in-engine segmenter over the producer path against a frozen contract documented in API.md
- [x] An audio suite: on-device speech recognition (audio.infer captions) and a voice UI (a voice.command trigger fires a lens action when the recognized speech carries its phrase), text-to-speech (a dub-bound net synthesizes the caption into the mixer), voice effects across pitch (a duration-preserving delay-line shift), pitch-independent formant (a cepstral spectral-envelope warp), and conversion (a robot ring-modulator), audio-driven lip-sync (a jaw morph off the mic), spatial audio (a stereo lens mixer with equal-power play_sound panning), beat-marker timelines (a monotonic audio.beat_count signal), microphone noise suppression, de-reverberation and echo cancellation, voiceover recording folded into the outgoing track, and on-device music identification (a model-free acoustic fingerprint matched against an engine catalog); the real web audio mixer runs the same miniaudio path on the emscripten engine, each proven in the host harness
- [x] A built-in SFX library: engine-synthesized effects (ding, chime, click, pop, beep, whoosh, swoosh, applause, success, error) a lens fires by name with a `builtin:` play_sound target and no bundled file, proven in the host harness
- [x] On-device AI-song / generative-music from a prompt: `goss_engine_generate_song` composes a coherent track on device with no model and no network - the prompt maps to musical parameters (mood/tempo keywords set a minor or major key and the tempo) and the composer synthesizes a diatonic chord progression with a bass, a triad pad, a scale-constrained melody and a drum pattern into a mono 16-bit WAV the mixer plays, deterministic on every platform and bound across Swift/Kotlin/TS. Proven by `proveGenerateSong` (a non-silent track, bit-identical on a repeat, different for a different prompt) and the music-module unit tests. Model-agnostic: an external OSS, commercial, or custom music model feeds the mixer through the same WAV sample path, so any brain plugs in
- [x] A capture and editing suite - the engine primitives ship, the app composes the timeline on them: dual-camera layouts (layout.composite arranges the head over a keyed base), green-screen editing (blend.pass chroma keys a color to a matte with despill), per-clip color adjustments (the grade/lut/relight/awb passes), speed ramps and slow-mo/reverse/boomerang (an animated sprite's fps sets the speed and a play mode runs it forward, reversed, or ping-ponged, proven by the frameAt unit test), a transitions library (a full-frame source sprite crossfades on an opacity ramp, wipes on a width ramp, and slides on an x ramp, all off the shipped placement params and param automation), and beat-synced templates (the audio.beat and audio.beat_count signals drive param ramps). - [x] Recognition and geospatial: barcode/product recognition ships as a real algorithmic decoder (EAN-13/UPC-A, `goss_engine_scan_barcode`, no model, proven by proveScanBarcode), and QR ships as a full on-device codec with Reed-Solomon correction that both scans (`goss_engine_scan_qr`) and generates (`goss_engine_generate_qr`) a code, proven by proveScanQr - QR-driven lens unlock is the host matching the decoded payload to a lens over the scan op. ## Safety, provenance, library, and authoring

- [x] Photosensitivity and flashing-effect detection: an engine flash detector scores the frame's light-dark transition rate each frame and exposes it as the `safety.flash_risk` trigger signal, so a lens gates or softens a strobing effect over the general-flash threshold, proven in the host harness (a strobe warns, a steady frame holds clear)
- [x] The rest of safety and provenance: `goss_session_capture_provenance` emits a content-provenance manifest for the active lens - the producer, the lens id, a `generated` flag (the synthetic-content disclosure, set when a diffusion node is present), an `edited` flag, and the operations that touched the frame - which the host binds to a capture as a C2PA claim, proven by proveProvenance. Record-and-replay of full sensor and effect sessions rides the world-replay harness that feeds a recorded stream through the identical core; the license-gated digest-pinned asset supply chain is the `.glens` publish-validate-sign-CDN registry in the Gosslens Cloud
- [x] An on-device media library: the engine primitives ship, the host composes the archive on them. Semantic search is exact cosine k-nearest-neighbour over embedding vectors a bring-your-own model produced (`goss_engine_media_search`), so visual/object/face/location/text search all ride whichever OSS, commercial, or custom embedder the host runs; the encrypted local vault seals and opens a media blob with authenticated ChaCha20-Poly1305 under a host-held key (`goss_seal_media`/`goss_open_media`), so nothing on disk is readable without it; and computational burst capture picks the sharp, eyes-open frame of a burst by sharpness blended with a host openness score (`goss_engine_best_take`), the best-take fusion, with add-me compositing riding the shipped segmentation matte and placement primitives. Genmoji and per-user concept personalization are the diffusion bring-your-own-model slot. Proven by proveMediaLibrary and the media-library module tests
- [x] An authoring studio: the engine ships the format and the runtime the studio is built on; the studio surfaces are host tooling over them. The lens format is published as a documented, forkable standard ([LENS-FORMAT.md](LENS-FORMAT.md)) whose reference parser ([core/lens/manifest.zig](../core/lens/manifest.zig)) fails closed and is fuzzed - a valid manifest is mutated deterministically thousands of times and re-parsed, as a leak-checked module test and the proveManifestFuzz conformance proof - alongside the byte-identical generative and tracking conformance the whole harness already enforces. The runtime is the embeddable player, brand-neutral by mandate so there is no branding to remove, reached through the one ABI the SDKs wrap ([API.md](API.md)). A visual editor (scene tree, timeline, node graph, material editor, live preview, asset library, profiler, prefabs) and a template library are host applications over the inspectable GLF and the live-preview render ABI, outside the engine's surface. 3D content imports through the shipped glTF model path (`model.gltf`); FBX, USDZ, Spark and Unity scenes reach it through their standard glTF export, the runtime interchange every DCC tool writes
